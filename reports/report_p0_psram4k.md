# Tang Nano 4K の内蔵 PSRAM（HyperRAM）の P0（2026-11-03）

## 結論
- GW1NSR-4C の SiP に入っている HyperRAM に、オープンなツール（4K の土台と同じ、手元で直した Apicula と chipdb）で作った回路から読み書きできた。
- 8 MB（4M ワード）全体のランダムなアドレス 300 語で、書いて読み戻して不一致 0 件。端のアドレス（0、1、中央、最後の語）も正しい。
- デバイスは Winbond と見られる（ID0 = 0x0C86。製造者のコード 6）。CR0 = 0x8F2F は、レイテンシ 7 クロック、固定の 2 倍レイテンシという既定値の読み方と合う。
- 書き込みのレイテンシは、実機で 13 と分かった（CA の後の CK のサイクルで数えた値）。読み出しは RWDS の切り替わりでデータを取るので、レイテンシを知らなくても読める。
- **注意**: Apicula の chipdb は HyperRAM を 2 チャンネル分持っている。2 つ目のチャンネルの位置は、4K では上端の JTAG のピン（TDI/TDO/TMS/TCK）と DONE に重なるので、実在しないとみられる。ポートを `[1:0]` で宣言すると、JTAG のピンを出力にしてしまう。1 ビットで宣言し、合成の後で `O_hpram_ck[0]` などに名前を変えて、1 つ目のチャンネルだけを置いた。

## 1. 内蔵のピンの置き方
- Apicula 0.35 の chipdb の `sip_cst`（GW1NSR-4C、QFN48P）に、HyperRAM のピンの位置がある。nextpnr は、同じ名前の IO のセルがあれば、そこに自動で置く（`himbaechel/uarch/gowin/cst.cc` の `add_sip_constraints`）。
- チャンネル 0 は、すべて下端の行 19 にあり、パッケージのピンにはつながっていない。

| 信号 | 位置 |
|---|---|
| `O_hpram_ck[0]` | X22Y19 IOBA |
| `O_hpram_ck_n[0]` | X14Y19 IOBB |
| `O_hpram_cs_n[0]` | X14Y19 IOBA |
| `O_hpram_reset_n[0]` | X4Y19 IOBB |
| `IO_hpram_rwds[0]` | X28Y19 IOBB |
| `IO_hpram_dq[0..7]` | X6Y19 A/B、X13Y19 A/B、X23Y19 B、X24Y19 A/B、X28Y19 A |

- チャンネル 1 の位置（X1Y0、X2Y0、X4Y0 の B）は、IOT の番号に直すと IOT2A/B（TDI/TDO、ピン 3/4）、IOT3A/B（TMS/TCK、ピン 6/7）、IOT5B（DONE、ピン 9）にあたる。IOT の番号は X+1 で、LED のピン 10（IOT7A）が X6Y0 に置かれることで確かめた。ほかの 4K の利用者の例も 1 チャンネル（`[0:0]`）。
- ポートの名前の付き方:
  - `[0:0]` で宣言すると、セルの名前に添字が付かず、nextpnr が見つけられない（「Cell O_hpram_ck[0] not found」）。そのまま配置すると、ビルドが失敗する。
  - 1 ビットで宣言して、yosys で `cd top; rename O_hpram_ck O_hpram_ck[0]; …` とすると、チャンネル 0 だけが置かれる。データは `[7:0]` で宣言すれば、`IO_hpram_dq[0]` から `[7]` の名前になる。
- `tools/p0/psram4k/hram_probe.py` は、書き込む前に配置を確かめる。上端の行にある IO がクロックと LED だけで、IO の総数が 17 でなければ止まる。

## 2. 回路（`tools/p0/psram4k/hram_probe.v`）
- 1 回に 1 つの HyperBus の取引だけを行う。CK は 27 MHz の 4 分周（6.75 MHz）。半周期ごとに、2 クロックで「DQ/RWDS を出す → CK を切り替える」。
- CA の 48 ビットは 6 つの辺で送る（3 CK サイクル）。データシート（Infineon S27KL0642、同じ HyperBus の部品）の表 4-2 のとおり。
  - 読み出しは RWDS の切り替わりでバイトを取る。CK が遅いので、辺から 74 ns 後の値は十分に安定している。
  - 書き込みは、レイテンシ L を CTRL で与え、半周期 6+2L と 7+2L でデータを出す（RWDS は Low = 書き込み）。
- 読み出し 1 回は 20 CK サイクル以内（約 3 µs）で、tCSM（4 µs、85 ℃）を下回る。
- デバッグ用に、読み出し中の RWDS と DQ を 32 回分記録して読める。
- 4K の土台（JTAG ブリッジ、`base_regs`）の外付けの口に、`0x5000` でつないだ。

## 3. 実機の結果
| 読んだもの | 値 |
|---|---|
| ID0 | 0x0C86 |
| ID1 | 0x0001 |
| CR0 | 0x8F2F |
| 書き込みのレイテンシ 3〜12 | 書き込まれない（起動時の値 0x5F77 のまま） |
| 書き込みのレイテンシ 13 | 書いた値を読み戻せた |
| 書き込みのレイテンシ 14〜16 | 書き込まれない（1 語ずれて、マスクされたとみられる） |
| ランダムな 300 語（8 MB 全体） | 不一致 0 件、取引は毎秒約 205 回（記録の読み出しを含む） |

## 4. カメラにとっての意味（計算と見込み）
- 容量: 8 MB に、QQVGA のグレー（19.2 kB）なら約 400 枚、QVGA の RGB565（153.6 kB）なら約 50 枚、VGA の YUV422（614 kB）なら 13 枚入る。
- 書き込みの速さ: この遅い CK（6.75 MHz）でも、1 回の取引で約 10 語（tCSM の範囲で）を書けば、数 MB/s が出る見込み。カメラの平均（QQVGA の Y で数百 kB/s）には十分。行の途中の速い区間は、BSRAM の小さな FIFO で吸収する。
- 読み出しの速さは、今と同じく JTAG で約 48 kB/s。PSRAM で変わるのは「大きな画像やカラー」と「センサーの速さで続けて撮り、後でゆっくり読む」ことで、ホストへの転送の速さは変わらない。

## 5. 確かめられなかったこと
- 連続の書き込み（バースト）と、温度の高いときの tCSM（1 µs、125 ℃）。
- CK を速くしたとき（PLL、DDR の IO の部品）の動き。
- チャンネル 1 が本当に無いこと。Gowin のデータシートの PSRAM の節は読んでいない。
- Winbond の型番とデータシート。読んだのは Infineon の同じ方式のデータシート。
